# Hard Quiz — текущий интерфейс

Обновлено: 2026-10-06. Главная опубликована через PR #6, компактная игра — через PR #7, техническое исправление lint — через PR #8 (`main` / `7408b8fd1a51d9c00a4b8f115863b92e74144372`). Обновление результата UI-02 реализовано в `feat/result-screen`; публикация этого выпуска проверяется по CI и Vercel.

Проект использует Vite, React, TypeScript, Tailwind, Supabase и Vercel. Публичный интерфейс — на английском. Основной сайт: https://hard-quiz.com. Изменения `main` публикуются существующей интеграцией GitHub → Vercel; успех конкретного выпуска требует проверки статуса и опубликованной страницы.

## Главная и навигация

На главной реализован согласованный сбалансированный вариант: форма квиза слева, компактный Daily справа, короткая ссылка на статью ниже. На мобильных экранах панели располагаются друг под другом. Рекорды вынесены в навигацию и меню аккаунта.

| Область | Файл / маршрут |
|---|---|
| Главная, наличие вопросов и запуск | `frontend/src/components/StartScreen.tsx` / `/` |
| Каталог, порядок и подписи категорий | `frontend/src/hooks/useQuizCatalog.ts` |
| Выбор категории и сложности | `frontend/src/components/QuizFilters.tsx` |
| Навигация и меню аккаунта | `frontend/src/components/Layout.tsx` |
| Стили нового интерфейса | `frontend/src/homepage.css` |
| Публичный рейтинг | `frontend/src/pages/LeaderboardPage.tsx` / `/leaderboard` |
| Личные рекорды | `frontend/src/pages/ProfilePage.tsx` / `/profile` |
| Редактирование ника | `frontend/src/components/NicknameModal.tsx` |
| Маршруты и защита профиля | `frontend/src/App.tsx`, `frontend/src/PrivateRoute.tsx` |

Категории и сложности загружаются из базы. Главная скрывает категории без вопросов, но рейтинг и профиль сохраняют доступ к историческим результатам всех категорий. `Movie Stills` — подпись существующей категории `All movies`; ID не меняется. Из выбранного уровня отображаются фактические `time_limit_secs` и `lives`.

Состояния загрузки, ошибки и пустого набора предусмотрены. Проверка наличия вопросов блокирует запуск до успешного ответа. Запоздавшие ответы предыдущего выбора игнорируются. Ошибки можно повторно проверить кнопкой Try again.

Личный профиль использует существующий `user_best`. Рейтинг использует RPC `get_leaderboard`. Смена ника использует существующий `upsertProfile` и исключает собственный user ID из проверки занятости. Гость направляется на вход с сохранением целевого `/profile`.

Daily и часовой пояс `America/Chicago` не изменены. Миграции и административные изменения базы не требуются.

## Обычная игра — /play

`GameScreen.tsx` отображает один компактный блок: категория/уровень/номер вопроса, целое изображение, таймер с подписью Time left, четыре ответа, результат выбора, Score/Lives и Elapsed. На `/play` Layout скрывает обычные навигацию, футер и автоматическое окно ника. Сам игровой экран содержит бренд и Exit quiz с подтверждением.

`src/game/useNormalGame.ts` управляет явными состояниями загрузки настроек, вопроса, картинки, готовности, проверки ответа, обратной связи, ошибок и завершения. Таймер стартует после картинки, использует абсолютный дедлайн и продолжает идти в другой вкладке. Ответ блокируется синхронно. После ошибки/таймаута правильный вариант не раскрывается. API-ошибка проверки повторяет уже выбранный ответ; жизни за сетевые ошибки не снимаются. Паузы — 900/1800 мс.

`get_question` получает `p_exclude_ids`; повтор или некорректные данные вызывают восстановимую ошибку. Исчерпание набора завершает игру с причиной `completed`; пустой начальный набор показывает выбор другой игры. Рабочая трёхпараметровая сигнатура проверена чтением API, серверные определения функций не менялись.

`src/game/resultStorage.ts` сохраняет точный итог до отправки, повторяет неудачные записи `upsert_user_best` для исходного пользователя и хранит последний результат гостя на устройстве. `pagehide` использует `keepalive`; перезагрузка/возврат в завершённую запись истории показывают результат, без продолжения сеанса. Сервер по-прежнему хранит личные рекорды, а не новую историю всех попыток. Очередь не переносит гостевые или чужие результаты в аккаунт. Для восстановления документа до `pagehide` в собственном sessionStorage поддерживается контрольный снимок.

`src/game/navigationGuard.ts` устанавливает проверку браузерного Back до обработчика BrowserRouter: отмена возвращает исходную запись истории, сохраняя игру и её таймер.

`src/game.css` учитывает `100dvh`, безопасные отступы и низкие экраны. Картинки любых пропорций используют `contain`, названия ответов переносятся без многоточия. В горизонтальном окне изображение и ответы располагаются рядом. Для очень низкого вертикального окна используются два столбца ответов.

## Результат игры — /result

`ResultScreen.tsx` и `src/result.css` реализуют компактную карточку в стиле главной: категория и сложность, причина завершения, крупный счёт, Quiz duration, личный рекорд вошедшего пользователя, Play again и Back to home. View leaderboard открывает `/leaderboard?category=<id>&difficulty=<id>`; рейтинг проверяет параметры по текущему каталогу и сохраняет их после перезагрузки. Ручная смена фильтров остаётся доступной.

`GameResult` сохраняет прежние счёт, время, настройки, владельца и причины `out-of-lives` / `completed` / `exit`. Новые необязательные поля содержат названия режима, время завершения и подтверждённые данные рекорда. Результаты предыдущего выпуска остаются читаемыми; подписи для них восстанавливаются из каталога.

До обычной отправки `upsert_user_best` считывается предыдущий рекорд, после успешной отправки — фактический серверный рекорд. Поздравление отображается только при подтверждённом первом или улучшенном рекорде этой свежей попытки. При равном счёте улучшение времени определяется по фактическому изменению серверного значения, без предположения о направлении сортировки. Ошибка чтения не блокирует отправку и не создаёт награду. Запрос `pagehide` с keepalive отправляется сразу, без ожидания сравнения.

UI различает Syncing, Synced with your account, локальную запись гостя и ошибку отправки с Retry. Гостевые результаты не отправляются в аккаунт и рейтинг; приглашение Log in сохраняет возврат на /result и объясняет пользу для следующих игр. Недоступное хранилище не выдаётся за успешную запись. Для аккаунта повторяется неизменный итог исходного пользователя; поздняя отправка старой попытки не заменяет последний результат и обновляет показ личного рекорда.

При загрузке авторизации результат не подменяется гостевым. Данные маршрута и устройства проверяются по владельцу и структуре. Повторный просмотр обозначается Last quiz result; при отсутствии данных показываются No result yet и Start a quiz, без фиктивных нулей. Локальная запись не является новой серверной историей всех попыток.

## SEO и проверки

Canonical, RSS, Organization JSON-LD и социальные метаданные сохраняются. Публичный `/leaderboard` включён в генератор sitemap; приватный `/profile` имеет noindex и не входит в sitemap.

Для UI-02 проходят 70 Chromium E2E, включая 25 проверок результата, 5 размеров экрана результата и прежние сценарии игры, авторизации, Daily, профиля, админки и блога. Проверены ошибки синхронизации и чтения рекорда, повторная отправка, отсутствие/повреждение результата, смена аккаунта, отказ доступа к хранилищу, клавиатурный повторный запуск и запоздавшая отправка старого результата. ESLint — 0 ошибок / 0 предупреждений; typecheck и production-сборка проходят. Тесты используют изолированный API, без записи тестовых рекордов в production.

Команды в `frontend/`:

```sh
npm ci
npm run build
npx tsc --noEmit -p tsconfig.app.json
npm run typecheck
npm run lint
npm run test:e2e
```

Playwright перехватывает запросы Supabase и использует тестовые ответы. Локальный сервер тестов всегда запускается с изолированным тестовым URL и placeholder, даже если CI передал production secrets: keepalive после закрытия страницы не должен попасть в рабочую базу. Существующий сервер не переиспользуется. Production по-прежнему получает настройки из Vercel.

`tests/game-screen.spec.ts` проверяет задержки изображения, единственный ответ/клавиши, неправильный ответ/таймаут без раскрытия, абсолютный дедлайн при фоне, сетевые ошибки и повторение, последний шанс, прохождение банка, подтверждение выхода, закрытие вкладки, перезагрузку, неизменность повторно отправленного итога и изоляцию аккаунтов. Геометрия проверяется на десяти размерах, включая 320×480, 320×568, 568×320 и 844×390, с длинным названием и разными пропорциями картинки. Ошибки и обратная связь дополнительно проверяются на тесных экранах.

`npm run lint` использует `--max-warnings=0` и проверяет весь актуальный код, включая Edge API и тесты. Архив `exports/`, сгенерированные `.cache/`, сборка `dist/` и отчёты тестов исключены. `npm run typecheck` проверяет приложение и конфигурацию Vite. Workflow CI запускает обе проверки, production-сборку и E2E.

`src/AuthProvider.tsx` содержит только провайдер-компонент; `src/AuthContext.ts` содержит общий контекст, типы и `useAuth`. Пути импортов `useAuth` у потребителей сохраняются. Аналогично `GalleryCollector.tsx` содержит провайдер, `galleryContext.ts` — контекст и регистрацию постеров. Галерея получает ключ статьи, чтобы автоматическая обложка не использовала изображения предыдущей публикации.

`src/api.ts` описывает используемые клиентом поля профилей, серий Daily и истории администратора. Возвращаемые данные неиспользуемых RPC с непроверенной структурой остаются `unknown`. Это клиентская типизация, не подтверждение серверных определений или новая валидация SQL.

GA-команды и параметры типизированы в `src/analytics/ga.ts`. Единственное исключение `prefer-rest-params` сохраняет официальный `dataLayer.push(arguments)` и не отключает правило в остальных файлах. Браузерный тест проверяет форму очереди и события начала, ответа и завершения игры.

`tests/site-regression.spec.ts` дополнительно проверяет email/Google redirects на локальном API, локальный выход и защиту профиля, создание ника, Daily и его серии, историю/поиск админки, автоматическую галерею между статьями и загрузку публичных маршрутов без JS-исключений. Тестовый GA ID изолирован; запросы Google tag заглушены.

Архивные `frontend/exports/` и сборочные `backend/static/` не являются целевыми исходниками этого изменения.
