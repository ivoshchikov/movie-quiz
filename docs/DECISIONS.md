## UI-01 — сбалансированная главная

Дата: 2026-10-05.
Статус: реализовано в `feat/balanced-homepage`; публикация проверяется отдельно по статусу Vercel и сайту.
Основание: владелец выбрал вариант «Сбалансированный» и поручил самостоятельно перенести его на главную.

- Главная содержит короткое вступление, форму запуска квиза, компактный Daily Challenge и одну ссылку на статью.
- Основная кнопка запуска выделена фиолетовым; Daily остаётся вторичным действием.
- Навигация: Play, Daily, Leaderboard, Blog. Правила доступны в футере.
- Публичный рейтинг расположен на `/leaderboard`; личные рекорды — на защищённой `/profile`.
- На момент выпуска главной меню содержало смену ника, выход и Admin. Решением UI-05 ниже смена ника удалена; выход и Admin сохраняются.
- `All movies` отображается как `Movie Stills` в новом интерфейсе; идентификаторы и названия в базе не меняются.
- Главная показывает категории с вопросами. Новые категории появляются автоматически после наполнения банка.
- Таймер и жизни берутся из `difficulty_level`. Запуск доступен после проверки вопросов для выбранной пары.
- Игровые правила, сохранение результатов, Daily и его часовой пояс `America/Chicago` остаются существующими.

Выбор этого интерфейса не утверждает новые игровые режимы или миграцию данных.

Главная опубликована: PR #6, production main `57e493c171b6387f4c8996bc0c25fcdb4877457a`.

Проверки реализации: сборка Vite с генерацией RSS/sitemap, TypeScript, ESLint новых и переработанных компонентов, Playwright на локальных ответах Supabase. Фактическое состояние выпуска фиксируется в pull request и статусах соответствующего commit.

## PLAY-01 — компактная обычная игра, пункт UI-01 дорожной карты

Дата: 2026-10-06.
Статус: реализовано в `feat/compact-game-screen`; публикация подтверждается отдельно статусом Vercel и проверкой production.
Основание: владелец поручил реализацию согласованного обсуждения `/play`, тестирование и выпуск на production.

- Цель — максимальный счёт; четыре ответа, +1 за правильный, ошибка/таймаут расходуют жизнь. Уровни, их время и жизни берутся из существующей базы.
- Один игровой блок в стиле сбалансированной главной. На экране игры остаются бренд и Exit quiz; обычная навигация и футер скрыты.
- Изображение показывается целиком через `object-fit: contain`, в том числе вертикальное. Высота блока учитывает доступное окно; для низких и горизонтальных экранов предусмотрены отдельные компоновки.
- Вопрос начинает отсчёт после загрузки настроек, вариантов и изображения. Во время загрузки и проверки ответа кнопки недоступны. Повторное нажатие или клавиша не создают повторный ответ.
- Дедлайн основан на `Date.now()`: смена вкладки не ставит вопрос на паузу. Неуспешная проверка API сохраняет выбранный ответ и допускает повторную проверку без штрафа за сбой сети.
- Автоматический переход: 900 мс после правильного ответа, 1800 мс после ошибки/таймаута. Запись статистики не задерживает переход.
- После ошибки или истечения времени правильный ответ не выделяется и не сообщается. Подсвечивается только выбранный ответ, если он был дан.
- Все вопросы без повторов запрашиваются через существующий `get_question` с `p_exclude_ids`. Пустой начальный банк и исчерпанный банк различаются. Исчерпание с оставшимися жизнями заканчивается поздравлением.
- Общее время по-прежнему считается по часам от начала сеанса, включая загрузку вопроса и обратную связь; подпись — Elapsed.
- Exit quiz и бренд открывают подтверждение с судьбой результата. Назад в браузере также требует подтверждения; обновление/закрытие используют штатное предупреждение браузера, если он его поддерживает.
- Подтверждённый выход, уход со страницы, обновление и закрытие завершают сеанс. Итоговый счёт и время фиксируются один раз. Восстановление страницы ведёт к результату, без продолжения игры.
- Итог хранится на устройстве. Для вошедшего пользователя отправляется существующий `upsert_user_best`; правила обновления личного рекорда на сервере не меняются. Гостевой результат остаётся на устройстве и не записывается в чужой аккаунт после входа.
- При уходе страницы отправка использует `fetch` с `keepalive`. Перед запросом итог помещается в локальную очередь. При сетевом сбое повторная отправка выполняется после возвращения онлайн/входа/открытия сайта, только для исходного user ID, с неизменными счётом и временем.
- Наличие RPC не считается проверкой серверной защиты результатов. SQL, RPC и RLS не изменялись; сохранение через браузер требует доступного хранилища. Принудительное завершение процесса браузера не гарантирует выполнение `pagehide`; собственная вкладка восстанавливает последний контрольный снимок при повторной загрузке документа.

В выпуске PLAY-01 изменения `/result` ограничивались причинами завершения, поздравлением, временем, статусом сохранения и повторным запуском. Полное обновление UI-02 согласовано отдельно и описано в RESULT-01 ниже.

Игра опубликована: PR #7, production main `214766435ccbb480cf2fbeea40bcb45b7d79e9a2`.

6 октября владелец отложил добавление Leaderboard и любых ориентиров лидеров на `/play`. Экран игры сохраняет существующую композицию; к идее можно вернуться отдельным обсуждением.

## TECH-01 — чистый lint и регрессионные проверки

Дата: 2026-10-06.
Статус: опубликовано через PR #8; production main `7408b8fd1a51d9c00a4b8f115863b92e74144372`. Успех Vercel и работа гостевой игры проверены после публикации.
Основание: владелец поручил исправить все ошибки проверки качества кода и убедиться в штатной работе сайта и игры.

- ESLint проверяет актуальный код, включая `frontend/api/`. Архив `exports/`, сгенерированные `.cache/`, `dist/` и отчёты тестов исключены; архивные копии не изменяются.
- `npm run lint` требует ноль ошибок и предупреждений. Правила TypeScript, React Hooks и Fast Refresh сохраняются.
- В API типизируются используемые клиентом профили, серии Daily и история администратора. Неиспользуемые ответы RPC без проверенной структуры представлены `unknown`, а не выдуманными полями. Сигнатуры RPC, SQL, RLS и правила записи данных не меняются.
- Контексты авторизации и галереи вынесены из файлов компонентов. Существующий импорт `useAuth` сохраняется. При смене статьи галерея создаётся заново и не переносит постеры из предыдущей публикации.
- GA имеет типы команд и параметров. Очередь сохраняет официальный формат Google `Arguments`, подтверждённый браузерным тестом; для этой единственной строки документировано исключение `prefer-rest-params`, без глобального отключения правила.
- CI дополнительно проверяет lint, TypeScript и production-сборку с генерацией RSS/sitemap. HTML-отчёт Playwright не запускает сервер после неуспешных тестов.
- Браузерные проверки авторизации, профиля, Daily, админки и галереи используют локальные ответы API. Тестовый Google tag заглушён; тестовые события не отправляются в Google.

Игровые правила, макет `/play`, часовой пояс Daily и зависимости сохраняются. Это техническое исправление, не внедрение остальных пунктов UI-дорожной карты.

Локальная проверка: ESLint — 0 ошибок / 0 предупреждений, `npm run typecheck` и `npm run build` проходят, все 45 Chromium E2E проходят, `git diff --check` чистый. В сборке остаются информационные предупреждения о возрасте Browserslist и размере общего JS-бандла; обновление зависимостей и разделение бандла не входят в этот выпуск. Реальные действия OAuth/письма и записи в production проверками не выполняются.

## RESULT-01 — результат игры, пункт UI-02 дорожной карты

Дата: 2026-10-06.
Статус: опубликовано через PR #9 (`6750105cc063dfd3d80c4f5b1c8c223f2fa19f53`). Оба CI workflow и production-деплой Vercel успешны; реальная гостевая игра, результат, повторный запуск и переход к рейтингу нужного режима проверены после публикации.
Основание: владелец согласовал все пункты обсуждения /result и поручил внедрение, тестирование и публикацию.

- Компактная карточка в стиле главной с категорией и сложностью, крупным счётом и подписью point/points, Quiz duration и личным рекордом вошедшего пользователя. Процент точности не добавляется.
- Основные действия — Play again с теми же настройками и Back to home. View leaderboard открывает рейтинг той же категории и сложности; переданные фильтры проверяются по каталогу.
- Заголовок при досрочном завершении — Quiz ended. Выход, уход, обновление и закрытие завершают сеанс; переключение вкладки сохраняет работающий таймер.
- За прохождение всего банка с оставшимися жизнями показывается All questions completed!; это не означает отсутствие ошибок. Правильные ответы после ошибок/таймаутов не раскрываются.

- При запрете браузерного хранилища результат остаётся видимым в текущем документе, с честным сообщением. Автоматическая и ручная отправка сохраняют исходные счёт, время и владельца. Поздний ответ старой попытки не перезаписывает свежую.
- Повторное открытие обозначается Last quiz result; отсутствие результата — No result yet и Start a quiz. Проверяются загрузка авторизации, смена пользователя и повреждённые данные.
- Мобильные кнопки располагаются вертикально. Длинный экран допускает естественную прокрутку; содержимое и действия доступны, горизонтального выхода нет. Сохраняются видимый фокус и клавиатурный запуск.

Проверки: 70 Chromium E2E, typecheck, production-сборка и ESLint без ошибок/предупреждений. SQL, RPC-контракты, RLS, зависимости, игровые правила и часовой пояс Daily не меняются. Следующее обсуждение — UI-03 /daily; остальные пункты остаются предложениями.

## DAILY-01 — Daily Challenge, пункт UI-03 дорожной карты

Дата: 2026-10-07.
Статус реализации: `feat/daily-screen`. Публикация проверяется отдельно по соответствующим PR, CI, Vercel и действующей странице.
Основание: владелец согласовал все 12 рекомендаций Daily, включая исправление ошибок, мобильную версию и существующий порядок внедрения/проверки/выпуска.

- Один центральный блок в стиле главной, `/play` и `/result`. Рейтинг свёрнут и отсутствует во время вопроса.
- Daily играется только после входа; гостю даны понятные правила, настоящая кнопка входа с возвратом и ссылка на обычную гостевую игру.
- Просмотр не начинает попытку. Start Daily появляется после проверки статуса и подготовки вопроса; таймер и ответы запускаются после картинки и успешного `start_daily_session`. Ник выбирается заранее.
- Answer time считается отдельно для даты Daily по абсолютным часам и фиксируется при выборе. Новый день Chicago — новый таймер с нуля, правильный ответ продлевает только серию. Существующие RPC и поле `time_spent` сохраняются.
- Четыре равнозначных ответа, клавиши 1–4, целая картинка любой пропорции. После ошибки правильный вариант не раскрывается.
- Выбор, отправка и подтверждённый результат разделены. Сбой сохраняет неизменные ответ, дату и время; Retry сначала читает сервер. Итог показывает только подтверждённые сервером правильность и время, не исчезает после сохранения и обновляет серию.

- Leave Daily и Back объясняют судьбу попытки. Refresh/закрытие используют штатное предупреждение браузера. Неподтверждённый уже выбранный ответ не переносится на следующий день; можно повторить его запись для исходной даты или открыть сегодняшний Daily.
- Честные ошибки статуса, пустого/некорректного вопроса, изображения, запуска, сети, таймаута запроса, статистики, рейтинга и localStorage имеют восстановление. Смена аккаунта и поздние ответы изолированы. Web Locks и серверная перепроверка уменьшают повторные запросы между вкладками.
- Личная статистика компактна: Current streak / Best streak в днях, число правильных Daily ниже. Рейтинг сохраняет Active today / All-time best, 5/20 строк, собственную строку и Retry.
- Следующее задание показывается обратным отсчётом до полуночи America/Chicago с корректным DST. Мобильные экраны и клавиатурный фокус проверены; Share on X содержит дату и общий результат без ответа.

Локальная проверка: 112 Chromium E2E (42 новых Daily), ESLint — 0 ошибок / 0 предупреждений, TypeScript, production-сборка и `git diff --check` проходят. Тестовый API изолирован, тестовые попытки и рекорды в production не записываются. SQL/RLS/серверные определения не получены, не меняются и не объявляются проверенными. Действующие серверные правила одной попытки сохраняются.

## LEADERBOARD-01 — публичный рейтинг, пункт UI-04 дорожной карты

Дата: 2026-10-07.
Статус: опубликовано на https://hard-quiz.com/leaderboard. Реализация подготовлена в `feat/leaderboard-screen`; выпущенный commit — `aed9bcf4888970159f610c8b2e2bdffe5490549f`.

- Один компактный блок: заголовок, короткие фильтры, рейтинг, личный рекорд и Play this quiz. Категории на телефоне — select, сложность — доступные кнопки. Фильтры записываются в URL и восстанавливаются при reload / Back / Forward; посторонние параметры сохраняются, неверные ID исправляются через replace.
- Показаны до 10 / 20 участников, с фактическим числом строк и без выдуманного общего числа игроков. RPC получает одну дополнительную строку для проверки наличия следующей части. Первые три места обозначаются компактными цветными номерами; счёт важнее времени, длинные имена переносятся целиком.
- Quiz duration сохраняет текущую длительность обычного сеанса: целые секунды от `startedAt` до завершения, включая загрузки, обратную связь и время в фоне. Итог фиксируется в `elapsedSecs`, отправляется существующим `upsert_user_best.p_time`, считывается как `user_best.best_time` / `get_leaderboard.best_time`. Метод подсчёта не меняется. Пояснение доступно в How ranking works.
- Список сохраняет порядок существующего RPC, включая равенства. SQL-функция не предоставлена; направление сравнения времени и правила равенства не объявляются проверенными и не заменяются клиентской сортировкой.
- Вошедший пользователь видит подтверждённый личный рекорд выбранного сочетания с отдельными загрузкой, ошибкой и Retry. Публичный список не зависит от успешности личного запроса. Смена владельца исключает старые личные данные. Подтверждённое сохранение обычной игры обновляет соответствующие рейтинг и рекорд.
- Собственная строка помечается только при наличии совпадающего `user_id` в ответе. Публичное чтение production RPC 7 октября подтвердило поля nickname / best_score / best_time / updated_at без `user_id`. Совпадение никнейма не используется как доказательство личности; личная карточка работает через существующий фильтр user_best по user ID.
- Доступность игры читается отдельно для категории + сложности. Пустой доступный рейтинг приглашает поставить первый рекорд; пустой недоступный квиз поясняет выбор другого сочетания; исторические результаты остаются видимыми при нулевом числе вопросов. Неизвестный count считается ошибкой, а не нулём. До проверки Play this quiz недоступен.
